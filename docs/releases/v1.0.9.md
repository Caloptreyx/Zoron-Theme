- **Email templates are opt-in:** Zoron no longer restyles the panel's emails on install. Studio's **Layout → Email templates** has a new switch, **Use Zoron email templates**, off by default. Turned on (and the theme saved), the ten panel emails get Zoron's Carbon layout; turned off, the panel's own emails come back. The colour sync, logo and footer apply only while it is on.
- **Changing the email settings needs the email templates permission:** a theme save that changes any email setting also needs core's `email-templates.update`, as editing the templates in **Admin → Settings → Mail Templates** does. Saving the rest of the theme still needs only `settings.update` or `zoron-theme.update`.

### Upgrading from 1.0.8

1.0.8 used the Carbon layout for every panel email as soon as it was installed. After the upgrade the switch is off, so emails go back to the panel's own on the first boot. To keep the Carbon layout, turn on **Use Zoron email templates** in Studio and save.

Which templates Zoron changes, on that boot and every time the switch is turned on or off:

- A template with no saved HTML of its own gets Zoron's layout while the switch is on, and nothing is stored for it while it is off.
- A template whose saved HTML is exactly what Zoron wrote (or exactly 1.0.8's layout, saved unchanged in **Mail Templates**) is Zoron's: it is replaced when the layout changes and cleared back to the panel's own when the switch is off.
- A template whose saved HTML you edited, or wrote yourself, is never touched.

Turn the switch off and save before removing Zoron, so no template keeps the layout once its `zoron_email_*` colour variables are gone.
